# Звіт v4.1.3 (за рекомендацією аудиту v4.1.2, розд. 4)

Автор: В'ячеслав Плескач. 24.11.2026. Архітектуру не змінено; diff від v4.1.2 — `v4_1_2_to_v4_1_3.diff` (63 рядки).

## Що змінено
`looks_like_html()` — спільна перевірка для sync, verify і anomaly — посилена: BOM, пробіли, XML-декларація й
HTML-коментарі перед першим тегом ігноруються; маркери `<!doctype html`, `<html`, `<head`, `<body` шукаються в перших
4 000 символах (було 500 і `<body` лише там); `</html>` / `</body>` у кінці відповіді; щільність структурних тегів
(≥ 5 у перших 50 000 символах).

## Граничні тести (`tests/test_v4_1_3_html_edge.py`)
Дев'ять варіантів HTML — коментар перед `<html>`, `<head>` без `<body>`, BOM + DOCTYPE, BOM і пробіли + `<HTML>`,
XML-декларація, маркери після 500 символів, маркери лише в кінці, фрагмент без маркерів із щільними тегами, DOCTYPE
великими літерами — і три звичайні тексти з `<`, `>` і словом «html». Для кожного HTML: `looks_like_html` = True,
`txt_response_problem` не порожня, `fetch_verified_text` відмовляє, `anomaly --record` не дає `duplicate_of` і не змінює картку.

**На коді v4.1.2 — 16 FAIL:** `<head>` без `<body>`, маркери після 500 символів, маркери лише в кінці й щільні теги
без маркерів за Content-Type `text/plain` не розпізнавалися. Тобто підозра аудиту підтвердилася: така відповідь могла б
стати текстом редакції в sync і «доказом дубля» в anomaly. (За Content-Type `text/html` v4.1.2 їх уже відкидав.)

**Хибних спрацювань немає:** нову евристику прогнано по всіх 3 304 текстах копії архіву — 0 збігів, жодного
структурного тегу в жодному тексті.
